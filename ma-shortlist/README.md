# MA Shortlist

A free, independent website for MCST councils in Singapore that are changing managing agent (MA). It has three parts:

1. **Shortlist**: pick your development and see agents worth asking for a quote. They're ranked on public data only: developments managed nearby, developments of a similar size, clients kept or lost, accreditation and portfolio size.
2. **RFP pack**: a standard request for proposal with your scope, a timeline worked back from your start date, and one price schedule every agent fills in. You can print it, save it as PDF or download it for Word.
3. **Compare quotes**: type in each price schedule to see the yearly cost with GST, the cost per unit and per condo-manager hour, and a weighted score.

There's also a step-by-step guide, an agent directory and a methodology page. There are no accounts and no backend. What councils type stays in their browser.

```
ma-shortlist/
  web/                    the site: static files, no build step
    lib/                  scoring, distances, RFP timeline and quote maths (shared with the tests)
    data/                 generated by scripts/build-data.mjs; don't edit by hand
  scripts/                fetch-mcst.mjs → geocode.mjs → build-data.mjs
  data/
    current.json          the latest BCA list, tidied
    history/              who managed each MCST, one file per month the answer changed
    geocode-cache.json    postal code → coordinates
    ma-aliases.json       fixes for firm names (edit this)
    accreditation.json    the AMA (Registered) list (edit this)
  tests/                  npm test, npm run e2e
  PLAN.md                 what's built, what's next
```

## Where the data comes from

- **BCA's [Management Corporation Strata Title](https://data.gov.sg/datasets/d_1f9391a2f1476cdaf4f05a8d3a05c257/view) dataset** on data.gov.sg. It lists every MCST with its address, number of strata lots and managing agent, under the Singapore Open Data Licence.
- **[OneMap](https://www.onemap.gov.sg/)**, for the coordinates of each postal code.
- **SISV's [AMA (Registered) list](https://www.sisv.org.sg/ama-Registered-list.aspx)**, copied by hand into `data/accreditation.json`.

The **MA Shortlist data** workflow (`.github/workflows/ma-shortlist-data.yml`) refreshes everything on the 2nd of every month and commits the result. It also runs when the scripts or the two files you edit change. Every refresh saves who manages each MCST. Comparing those records over time shows which developments switched agent. Records start on 22 October 2026, because BCA's older dataset can't be read through the API. Switches only count in the shortlist once there are three months of records.

Placing postal codes on the map with OneMap takes about a second each, so each run stops after 30 minutes and the next run carries on. Until a development is placed, "nearby" falls back to the same postal district.

Names with no business word in them are not shown as managing agents. This covers people's names, "MCST" (self-managed) and placeholders like "N". Only firms with 3 or more developments are suggested in a shortlist, but every firm is listed under Agents.

## Going live on Cloudflare Pages (free, about 10 minutes)

1. Make a free account at [dash.cloudflare.com](https://dash.cloudflare.com/sign-up).
2. Go to **Workers & Pages → Create → Pages → Connect to Git**, and pick the `claudeprojects` repo.
3. Set up the build:
   - Project name: `ma-shortlist`. This gives you `https://ma-shortlist.pages.dev`. If the name is taken, pick another.
   - Production branch: `main`
   - Framework preset: **None**
   - Build command: leave empty
   - Build output directory: `ma-shortlist/web`
4. **Save and Deploy.** Every push to `main` republishes the site, including the monthly data commits. Other branches get their own preview addresses.

If Cloudflare created a **Worker** instead of a Pages project (its newer "Create" flow does this), the site deploys but shows **"No URLs enabled"**. To fix it, open the Worker, go to **Settings → Domains & Routes**, and enable the **workers.dev** route. The site is then at `https://<worker name>.<your subdomain>.workers.dev`.

### Adding a custom domain later

Buy a domain: a `.com` costs about US$10 a year at cost from Cloudflare Registrar, and a `.sg` about S$30–60 a year from an SGNIC-accredited registrar. Then open the Pages project → **Custom domains → Set up a domain**. Nothing in the site needs to change, because all its links are relative.

## Keeping the data clean

After each refresh, the **Build the site data** step in the workflow log lists:
- firms whose names look alike: if two are the same firm, add them to `merge` in `data/ma-aliases.json`
- accreditation names that didn't match a BCA name: fix the spelling in `data/accreditation.json`

To finish the accreditation list:
1. Open the SISV page and copy every firm into `data/accreditation.json` with its category.
2. Set `checked` to today's date and `complete` to `true`.

Until then, firms on the list get a badge, but accreditation isn't part of the score. That way no firm is marked down for a gap in our copy.

Pushing a change to either file reruns the workflow.

## Working on it locally

```
cd ma-shortlist
npm test                 # unit tests, including the data pipeline on the fixtures
npm run e2e              # browser tests on phone and desktop sizes (needs Playwright and http-server installed globally)
npm run refresh          # fetch, geocode and build real data (needs access to data.gov.sg and onemap.gov.sg)
npm run serve            # http://localhost:4174
```

Set `DATA_GOV_SG_API_KEY` (locally, or as a repository secret for the workflow) for data.gov.sg's higher rate limits. It works without one.
